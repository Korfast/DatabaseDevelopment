# Чек-лист проверки VideoHostingApp по ТЗ ЛР1-ЛР4

Проверяется вручную в `VideoHostingApp.exe` на базе `VideoHostingDB`.

ТЗ: `Основы Разработки Баз Данных/ТЗ/Лабораторная_работа№1.pdf` - `Лабораторная_работа№4.pdf`.

## 0. Подготовка

- [x] Рабочая ветка: `feature/3_related_tables_app`.
- [x] База `VideoHostingDB` создана и доступна в SQL Server.
- [x] Строка подключения в `App.config` указывает на актуальный SQL Server.
- [x] В таблицах есть тестовые данные для `Контент`, `Жанр`, `Правообладатель`, `Договор`, `Лицензия`, `Медиа_файл`.
- [x] Перед ручной проверкой зафиксированы ID существующих записей, которые можно использовать как FK.
- [x] Проект собирается через MSBuild без ошибок и предупреждений.
- [x] После сборки запускается `bin/Debug/VideoHostingApp.exe`.

## 1. ЛР1: структура базы данных

- [x] БД реляционная, таблицы связаны через первичные и внешние ключи.
- [x] Есть минимум 3-4 связанные таблицы; в проекте ожидаются:
  `Контент`, `Жанр`, `Контент_Жанр`, `Правообладатель`, `Договор`, `Лицензия`, `Медиа_файл`.
- [x] Ссылочная целостность работает:
  - [x] нельзя создать договор с несуществующим `ID_правообладателя`;
  - [x] нельзя создать лицензию с несуществующим `ID_контента`;
  - [x] нельзя создать строку `Контент_Жанр` с несуществующим контентом или жанром.
- [x] Есть ограничения `CHECK` и `DEFAULT`, не считая `PRIMARY KEY` и `FOREIGN KEY`.
- [x] Проверены не менее 3 разных ограничений:
  - [x] номер договора соответствует формату `АА-0000/00000`;
  - [x] путь к скану договора пустой или заканчивается на `.pdf`;
  - [x] дата начала лицензии не позже даты окончания;
  - [x] год выпуска контента в допустимом диапазоне;
  - [x] тип контента выбирается из допустимого списка;
  - [x] email/телефон правообладателя проходят ограничения формата.
- [x] В БД есть поля разных типов:
  - [x] изображение: `Контент.постер`;
  - [x] длинный текст: описание контента;
  - [x] список значений: тип контента, возрастной рейтинг, страна, тип лицензии;
  - [x] логический тип: `Лицензия.статус`.

- [x] Главное окно сохраняет положение/настройки при повторном запуске, если это предусмотрено настройками формы.
- [x] Подключение к БД выполняется через конфигурационный файл приложения.
- [x] Открываются все справочники:

## 3. ЛР2: CRUD в справочниках

- [ ] В каждом справочнике работает навигация по записям.
- [ ] В каждом справочнике можно добавить корректную запись и сохранить ее.
- [ ] В каждом справочнике можно изменить существующую запись и сохранить ее.
- [ ] В каждом справочнике можно удалить тестовую запись, если она не используется дочерними таблицами.
- [ ] После сохранения и повторного открытия формы изменения остаются в БД.
- [ ] Некорректные данные не приводят к падению приложения, а показывают сообщение об ошибке.
- [ ] В форме `Контент` можно загрузить постер из файла изображения.
- [ ] После сохранения и повторного открытия постер отображается в `PictureBox`.
- [ ] В форме `Жанры` при ошибке загрузки или сохранения показывается `MessageBox`, приложение не падает.

## 4. ЛР3: форма `Договор и лицензии (1:М)`

- [ ] Форма открывается через `Связи -> Договор и лицензии (1:М)`.
- [ ] Повторное открытие формы работает по Singleton.
- [ ] Навигатор листает договоры, поля договора меняются вместе с текущей записью.
- [ ] Подстановочное поле `Правообладатель` показывает реальное наименование, а не только ID.
- [ ] Грид лицензий показывает только лицензии текущего договора.
- [ ] Колонка с названием контента в лицензиях заполнена.
- [ ] При смене договора список лицензий перестраивается под новый договор.
- [ ] Можно добавить новую лицензию к текущему договору.
- [ ] При добавлении лицензии номер текущего договора проставляется через связь 1:М.
- [ ] `дата_добавления` для новой лицензии получает значение по умолчанию.
- [ ] Корректная лицензия сохраняется без ошибок.
- [ ] Некорректная лицензия с датой начала позже даты окончания показывает ошибку.
- [ ] Несуществующий `ID_контента` в лицензии показывает ошибку FK.
- [ ] После сохранения новая лицензия видна после перезапуска формы.

## 5. ЛР3: форма `Контент, жанры, файлы (М:М)`

- [ ] Форма открывается через `Связи -> Контент, жанры, файлы (М:М)`.
- [ ] Повторное открытие формы работает по Singleton.
- [ ] Навигатор листает записи контента.
- [ ] Вычисляемая колонка/поле `Название с годом` показывает формат `Название (Год)`.
- [ ] Грид жанров показывает жанры только для текущего контента.
- [ ] Жанр выбирается через подстановочную колонку, а не вводом сырого ID.
- [ ] Можно добавить жанр к текущему контенту и сохранить связь.
- [ ] Дубликат пары `ID_контента` + `ID_жанра` показывает ошибку, а приложение не падает.
- [ ] Грид медиафайлов показывает файлы только текущего контента.
- [ ] Вычисляемая колонка `Размер, МБ` показывает размер в мегабайтах.
- [ ] Медиафайлы на этой форме не редактируются, если форма задумана как просмотр связанного списка.

## 6. ЛР3: поиск, фильтрация, вычисляемые и подстановочные поля

- [ ] В форме `Правообладатели` поиск по выбранной колонке находит запись по части текста.
- [ ] Поиск не зависит от регистра букв.
- [ ] Поиск по несуществующему фрагменту показывает сообщение, приложение не падает.
- [ ] Фильтр по части текста сужает таблицу до совпадающих строк.
- [ ] Снятие флажка фильтра возвращает полный список.
- [ ] Ввод с апострофом или спецсимволом фильтра не ломает фильтр.
- [ ] В приложении есть минимум 1-2 вычисляемые колонки:
  - [ ] `Контент.Название_полное`;
  - [ ] `Медиа_файл.Размер_МБ`;
  - [ ] `Договор.Правообладатель_Наименование`;
  - [ ] `Лицензия.Контент_Название`.
- [ ] В приложении есть минимум 1-2 подстановочные колонки:
  - [ ] правообладатель договора;
  - [ ] контент лицензии;
  - [ ] жанр в связи `Контент_Жанр`.

## 7. ЛР3: обработка ошибок

- [ ] Проверены минимум 2-3 разные ошибки данных:
  - [ ] нарушение FK;
  - [ ] нарушение CHECK;
  - [ ] дубликат первичного/составного ключа;
  - [ ] некорректный тип значения в ячейке;
  - [ ] недоступная БД или неверная строка подключения.
- [ ] Ошибки показываются через понятный `MessageBox`.
- [ ] После ошибки приложение продолжает работать.
- [ ] Ошибки `DataGridView` в combo-колонках не завершают приложение.

## 8. ЛР4: запросы

По ТЗ ЛР4 в приложении должны быть реализованы отдельные запросы. В текущем коде видны стандартные `SELECT/INSERT/UPDATE/DELETE`, сгенерированные `TableAdapter`, но не обнаружены отдельные пользовательские формы/меню для запросов ЛР4. Этот блок нужно отметить как невыполненный, если такие формы не добавлены позже.

- [ ] Есть отдельный раздел меню или форма для запросов.
- [ ] Выполняется выборка из одной таблицы.
- [ ] Выполняется выборка с условием.
- [ ] Выполняется выборка из нескольких таблиц.
- [ ] Выполняется запрос с агрегирующими функциями.
- [ ] Есть запрос с полной структурой `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`.
- [ ] Есть запросы с параметрами разных типов данных.
- [ ] Для параметров проверяется корректность ввода.
- [ ] Есть подзапрос.
- [ ] Есть пользовательские операции изменения данных:
  - [ ] `INSERT`;
  - [ ] `UPDATE`;
  - [ ] `DELETE`.
- [ ] Параметрические `INSERT/UPDATE/DELETE` проверяют корректность параметров.
- [ ] Результаты запросов отображаются в форме приложения.
- [ ] Ошибки запросов показываются пользователю без падения приложения.
