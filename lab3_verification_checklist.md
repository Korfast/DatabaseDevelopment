# Чек-лист проверки ЛР3 (связанные таблицы)

Ветка: `feature/3_related_tables_app`. Проверяется вручную в запущенном
`VideoHostingApp.exe` на живой БД `VideoHostingDB` (DESKTOP-IJQ82VB\SQLEXPRESS).

## 0. Сборка

- [x] Проект собирается через MSBuild без ошибок.

## 1. Меню

- [ ] В главном меню появился новый пункт **«Связи»** между «Справочники» и
      «Справка», с двумя подпунктами: «Договор и лицензии (1:М)» и
      «Контент, жанры, файлы (М:М)».

## 2. `ContractDetailsForm` («Договор и лицензии»)

- [ ] Открывается без ошибок; повторное открытие через меню не плодит новое
      окно (singleton), а активирует уже открытое.
- [ ] Кнопки навигатора (⏮◀▶⏭) листают договоры; поля меняются вместе с
      записью.
- [ ] Подпись **«Правообладатель:»** показывает реальное имя (не пусто, не
      ошибка) для разных договоров — проверка
      `Parent(FK_Договор_Правообладатель)`.
- [ ] Грид «Лицензии по договору» показывает только лицензии текущего
      договора, а не все подряд.
- [ ] Колонка «Контент» в этом гриде показывает название контента (не
      пусто) — проверка второго `Parent()`-выражения.
- [ ] Добавление новой лицензии (кнопка «Добавить» в мини-навигаторе грида)
      + «Сохранить» — проходит без ошибок при корректных данных.

  Пример корректных данных для новой лицензии:

  | Поле | Значение | Комментарий |
  |---|---|---|
  | ID_лицензии | оставить пустым | генерируется автоматически (IDENTITY) |
  | ID_контента | `1` / `2` / `3` / `7` | реально существующие ID в таблице `Контент` |
  | Дата начала | `01.01.2026` | любая корректная дата |
  | Дата окончания | `31.12.2026` | должна быть ≥ даты начала (`CK_Лицензия_Даты`) |
  | Статус | галочка вкл/выкл | `bit`, ограничений на значение нет |

  Номер_договора трогать не нужно — должен автоматически проставиться
  значением текущего открытого договора (эффект 1:М-биндинга через
  `FK_Лицензия_Договор`). Пустое поле после добавления строки — баг.

  Отрицательный ID у новой строки до сохранения — нормально (клиентский
  временный IDENTITY-плейсхолдер), после «Сохранить» подменяется на
  реальный через `SCOPE_IDENTITY()`.

- [ ] Хотя бы 2 ошибки реально воспроизводятся и показывают понятный
      `MessageBox`, а не падение приложения:
  - дубликат номера договора,
  - несуществующий ID_правообладателя,
  - неверный формат номера договора / расширение пути к скану.

## 3. `ContentDetailsForm` («Контент, жанры, файлы»)

- [ ] Открывается без ошибок, singleton работает.
- [ ] Подпись **«Название с годом:»** показывает `Название (Год)` —
      проверка строкового `Expression` с `Convert()`.
- [ ] Грид «Жанры контента»: колонка «Жанр» — рабочий выпадающий список (не
      пустой), можно выбрать жанр и сохранить через мини-навигатор.
- [ ] Грид «Медиафайлы контента» (только просмотр): колонка
      **«Размер, МБ»** показывает реальное дробное число (не 0, не ошибка)
      — проверка `размер/1024.0/1024.0`.

## 4. `RightHolderListForm` — поиск/фильтр

- [ ] Ввести значение (например, часть названия правообладателя) в
      текстовое поле рядом с «Сохранить», нажать «Поиск» — курсор переходит
      на нужную строку по выбранной колонке грида.
- [ ] Поставить галочку «Фильтр» — грид сужается до совпадающих строк;
      снять галочку — грид возвращается к полному списку.
- [ ] Поиск/фильтр по несуществующему значению — показывает вменяемое
      сообщение, а не падает.

## 6. Известные и исправленные нюансы

- Столбец `Лицензия.дата_добавления` (`NOT NULL`, `DEFAULT getdate()` в
  БД) отсутствовал в типизированном `ЛицензияDataTable` (унаследовано из
  ЛР2). Исправлено в `ContractDetailsForm.cs` — значение по умолчанию
  (`DateTime.Today`) выставляется в коде после `Fill()`.
